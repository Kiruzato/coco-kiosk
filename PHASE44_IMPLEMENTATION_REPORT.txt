================================================================================
1. PROBLEM STATEMENT
================================================================================

When users asked general knowledge questions (e.g., "What is hydraulics?"), the
system would:

1. Find lexical matches in campus documents (e.g., "Soil Mechanics and Hydraulics
   Laboratory Custodian")
2. Grounding validation would pass (word "hydraulics" found)
3. But the semantic match was wrong (job title vs. subject definition)
4. Response would get suppressed with: "I couldn't confidently find information
   about hydraulics"

ROOT CAUSE: The system blocked LLM generation when it found lexical matches but
the semantic relevance was low. The LLM should instead generate a general
knowledge response.

================================================================================
2. SOLUTION: LLM-AS-FINAL-SYNTHESIZER ARCHITECTURE
================================================================================

All response paths now terminate in the LLM for final natural language
generation, while preserving:
- Deterministic routing
- Structured authority rules
- Policy enforcement
- Grounding validation
- Safety constraints

NEW 4-LAYER ARCHITECTURE:

    Query
      |
      v
    [GOVERNANCE LAYER] - Intent classification, authority rules, safety checks
      |
      v
    [RETRIEVAL LAYER] - Hybrid BM25 + Vector search, grounding validation,
                        semantic relevance scoring
      |
      v
    [EXTRACTION LAYER] - Deterministic extractors (deans, awards, dates, contacts)
      |
      v
    [LLM SYNTHESIS LAYER] - Final response generation (ALL paths end here)
      |
      v
    Response

================================================================================
3. RESPONSE MODES
================================================================================

| Mode                    | Trigger                              | Behavior                        |
|-------------------------|--------------------------------------|---------------------------------|
| EXTRACTOR_AUTHORITATIVE | Deterministic extractor matches      | LLM presents extracted data     |
| RAG_AUTHORITATIVE       | High semantic relevance + grounded   | LLM answers from documents only |
| RAG_SUPPLEMENTED        | Grounded but low semantic relevance  | LLM uses context if applicable  |
| GENERAL_KNOWLEDGE       | No campus relevance                  | LLM provides general answer     |

================================================================================
4. KEY FEATURE: SEMANTIC RELEVANCE SCORING
================================================================================

New scoring mechanism distinguishes meaningful matches from coincidental lexical
overlaps:

- HIGH: Query terms are semantically central to document content
- MEDIUM: Query terms appear but may be tangential (e.g., in titles/metadata)
- LOW: Lexical match only, semantic mismatch

Implementation factors:
1. Vector similarity score thresholds (high: 0.78, medium: 0.65)
2. Term position analysis (checks if terms in substantive content vs titles)
3. Query type analysis (definition queries get stricter semantic requirements)

15. BUG FIXES DURING IMPLEMENTATION
================================================================================

During testing, several bugs were discovered and fixed:

BUG 1: combine_hybrid_scores() return value unpacking
-------------------------------------------------------
File: response_orchestrator.py line 331-333
Issue: combine_hybrid_scores() returns tuple (reranked_results, detailed_scores)
       but code was assigning entire tuple to hybrid_scores

BEFORE:
```python
result.hybrid_scores = combine_hybrid_scores(retrieval_results, keyword_scores)
```

AFTER:
```python
result.hybrid_scores, _ = combine_hybrid_scores(retrieval_results, keyword_scores)
```

BUG 2: compute_confidence_score() parameter mismatch
----------------------------------------------------
File: response_orchestrator.py lines 352-357
Issue: Function expects list of scores, not single score and count

BEFORE:
```python
top_score = result.hybrid_scores[0][1] if result.hybrid_scores else 0.5
result.confidence_level, result.confidence_score = compute_confidence_score(
    top_score, len(result.documents)
)
```

AFTER:
```python
if result.hybrid_scores:
    scores = [score for _, score in result.hybrid_scores]
    conf_level, conf_metrics = compute_confidence_score(scores)
    result.confidence_level = conf_level
    result.confidence_score = conf_metrics.get("confidence_score", 0.0)
```

BUG 3: QueryLogger method name
------------------------------
File: app.py line 2603
Issue: QueryLogger has no log() method, only log_query()

BEFORE:
```python
query_logger.log(query=query, answer=..., sources=..., ...)
```

AFTER:
```python
query_logger.log_query(query=query, session_id=session_id, metadata={...})
```

================================================================================

Date: 2026-02-12
Status: COMPLETED

PROBLEM ADDRESSED:
------------------
For certain queries (especially math), the chatbot produced:
- Overly verbose, LaTeX-heavy responses
- Irrelevant grounding disclaimers ("This calculation does not relate to campus...")
- Not kiosk/voice-friendly output

SOLUTION IMPLEMENTED:
---------------------
Response Style Policy system that:
1. Detects query type/complexity before LLM synthesis
2. Applies appropriate formatting constraints via prompt engineering
3. Eliminates irrelevant disclaimers for non-campus queries
4. Optimizes for voice/kiosk UX by default

FILES CREATED/MODIFIED:
-----------------------

MODIFIED: campus_rag_chatbot/response_orchestrator.py
- Updated RAG_SUPPLEMENTED prompt (removed disclaimer instruction)
- Updated GENERAL_KNOWLEDGE prompt (added kiosk-friendly instructions)
- Added STYLE_HINTS dictionary for query-type-specific formatting
- Modified _synthesize_response() to use query analysis
- Added _strip_latex() method for post-processing

KEY PROMPT CHANGES:
-------------------

RAG_SUPPLEMENTED - BEFORE:
"Clearly distinguish between verified campus information and general knowledge"

RAG_SUPPLEMENTED - AFTER:
