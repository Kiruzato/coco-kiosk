================================================================================
OUTDOOR LOCATION SUPPORT
================================================================================

Convention: Use "_OUTDOOR" as marker value for building and floor fields

Flat Entity Format:
{
  "entity_id": "COVERED_COURT_1",
  "canonical_name": "Covered Court",
  "building": "_OUTDOOR",
  "floor": "_OUTDOOR",
  "campus": "Main Campus",
  "tags": ["sports", "outdoor", "court"],
  "status": "active"
}

Behavior:
- When building="_OUTDOOR" or floor="_OUTDOOR", entity is converted to OutdoorLocation
- OutdoorLocation has: location_id, campus_id, canonical_name, tags, aliases, description, landmarks, status
- "outdoor" tag is automatically added if not present
- OutdoorLocation entities are indexed in: outdoor_locations, alias_to_outdoor, outdoor_by_tag, outdoor_by_campus

Admin UI:
- Entity type radio selector toggles between "Room/Indoor Location" and "Outdoor Location"
- When "Outdoor Location" selected, building/floor fields are hidden
- On save, building and floor are automatically set to "_OUTDOOR"

================================================================================
TAG NORMALIZATION
================================================================================

Input: ["Engineering", " lab ", "LAB", "  sports  "]
Output: ["engineering", "lab", "sports"]

Rules:
1. Convert to lowercase
2. Trim whitespace
3. Remove special characters (except hyphen and underscore)
4. Remove duplicates
5. Sort alphabetically

Applied to:
- Entity creation
- Entity update
- Bulk import
- Validation endpoint

================================================================================
INDEX REBUILD BEHAVIOR
================================================================================

Trigger Points:
- After successful entity creation (POST /admin/entities)
- After successful entity update (PUT /admin/entities/{id})
- After successful entity deletion (DELETE /admin/entities/{id})
- After successful bulk import (POST /admin/entities/import)
- Manual trigger (POST /admin/index/rebuild)

Process:
1. Create new CampusQueryIndex instance
2. Load from directory_entities.json
3. Build all indexes (rooms, buildings, floors, outdoor, tags, aliases)
4. Replace global _cqe_index reference
5. Log statistics

Statistics Returned:
- rooms: Total room count
- buildings: Building count
- campuses: Campus count
- outdoor_locations: Outdoor location count
- aliases: Total alias count across all indexes

================================================================================
VALIDATION FLOW
================================================================================

1. Client submits entity data
2. EntityManager.validate_entity() called
3. Each field checked against rules
4. Errors collected (block save)
5. Warnings collected (allow save with notification)
6. Data normalized (tags, aliases, trimming)
7. If valid: normalized_data returned
8. If invalid: errors returned, save blocked

Warning Examples:
- "Building 'New Building' does not exist - will be created"
- "Campus 'Branch Campus' does not exist - will be created"
- "Floor 'Rooftop' has non-standard format"
- "Tags normalized: ['Engineering', ' lab '] -> ['engineering', 'lab']"

Error Examples:
- "entity_id is required"
- "canonical_name is required"
- "entity_id 'LIBRARY' already exists"
- "status must be 'active' or 'inactive', got 'pending'"
