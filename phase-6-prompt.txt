We are continuing the campus information kiosk chatbot built in Phases 1–5.
The system currently includes:
•	Conversational RAG for campus knowledge
•	Strict document grounding with citations
•	Hallucination guardrails
•	Confidence scoring
•	Structured logging
•	Web-based kiosk UI
In Phase 6, we are adding a dual-mode answering system.
________________________________________
Phase 6 Scope (Only Build What’s Listed Below):
1.	Query Intent Classification
o	Before retrieval, classify each user query into one of:
	campus → must use RAG and citations
	general → may use general AI knowledge
	ambiguous → requires clarification or safe fallback
o	Use a lightweight LLM-based classifier with a short prompt.
2.	Answer Routing Logic
o	If intent = campus:
	Run the existing RAG pipeline
	Enforce citations and hallucination guardrails
o	If intent = general:
	Skip document retrieval
	Use the LLM directly
o	If intent = ambiguous:
	Ask a clarification question OR
	Default to campus mode with strict refusal on low confidence
3.	Response Transparency
o	Clearly label each response as either:
	“Based on campus documents”
	“Based on general AI knowledge”
o	Do not mix modes in a single response.
4.	Safety Constraints
o	Never allow general-knowledge mode to answer campus-specific questions.
o	If campus retrieval confidence is low:
	Refuse or ask for clarification
	Do not silently fall back to general knowledge
5.	Logging & Observability
o	Log for each query:
	Classified intent
	Mode used (campus / general)
	Retrieval confidence (if applicable)
o	Store logs locally.
________________________________________
Constraints:
•	No UI redesign
•	No admin UI changes
•	No policy-based role expansion
•	No external classifiers or services beyond the existing LLM
________________________________________
Output Requirements:
•	Minimal, clean extension to existing code
•	Clear separation between:
o	Intent classification
o	Campus RAG answering
o	General knowledge answering
•	Example interactions demonstrating:
o	Campus-grounded question
o	General knowledge question (e.g., simple math)
o	Ambiguous question handling
Do not implement additional features beyond this scope. Focus on adding general knowledge safely and transparently.
