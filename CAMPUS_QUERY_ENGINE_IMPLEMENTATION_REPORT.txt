1. EXECUTIVE SUMMARY
================================================================================

The Campus Query Engine (CQE) is a deterministic, index-based query processing
system that provides 100% accurate location information without relying on
Large Language Model (LLM) inference for factual content. This implementation
supports the thesis positioning of CoCo as a "Deterministic Structured Campus
Query Engine with Controlled Generative Augmentation."

Key Achievements:
- 5 query intents fully supported (LOCATE_SINGLE, LOCATE_MULTIPLE, NEAREST, COUNT, LIST)
- 220 room entities indexed with O(1) lookup performance
- Structural proximity algorithm for NEAREST queries (4-tier hierarchy)
- 41/41 golden tests passing
- Backward compatibility with legacy directory query handling preserved
- Zero LLM calls for location facts - deterministic responses only

================================================================================
2. THESIS POSITIONING
================================================================================

Academic Argument:
"CoCo implements a Deterministic Structured Campus Query Engine with Controlled
Generative Augmentation, ensuring factual accuracy for location queries while
preserving natural language presentation capabilities."

Key Differentiators:
1. DETERMINISM: Location facts are never generated - they come from a verified
   entity registry indexed at startup
2. STRUCTURAL PROXIMITY: "Nearest" is defined via containment hierarchy, not
   geometric distance, matching user mental models
3. CONTROLLED AUGMENTATION: LLM is used ONLY for presentation formatting in
   non-CQE paths; CQE uses template-based formatting
4. GROUNDED RESPONSES: Every response traces back to indexed entity data

Anti-Hallucination Guarantees:
- Entity resolution uses exact alias matching against pre-indexed data
- No LLM interpolation or inference for building/floor/room information
- Template-based response generation ensures consistent output format
- Failed lookups return explicit "not found" messages rather than guessing

4.3 Phase 49: Query Executor & Response Formatter
-------------------------------------------------
Files Created:
  - campus_query_executor.py (480 lines)
  - campus_response_formatter.py (355 lines)
  - test_campus_query_engine.py (220 lines)

CampusQueryExecutor Methods:

  _execute_locate_single(query):
    1. Resolve target_entity via alias lookup
    2. Try room -> building -> campus resolution order
    3. Return single entity or "not found" message

  _execute_locate_multiple(query):
    1. Start with all active room IDs
    2. Apply filter intersection (AND logic)
    3. Sort by building, floor, room number
    4. Return filtered room list

  _execute_nearest(query):
    1. Resolve reference entity
    2. Determine target room type
    3. Execute structural proximity search:
       - Tier 0: Same floor (floor_id match)
       - Tier 1: Same building (building_id match)
       - Tier 2: Same campus (campus_id match)
       - Tier 3: Different campus (fallback)
    4. Return nearest rooms with proximity tier metadata

  _execute_count(query):
    1. Apply same filter intersection as LOCATE_MULTIPLE
    2. Return count only (no entity list)

  _execute_list(query):
    1. Check target_type: "department", "building", "campus"
    2. Aggregate unique values from index
    3. Return sorted list

CampusResponseFormatter Methods:

  format(result):
    - Routes to intent-specific formatter
    - Handles error/empty results gracefully

  _format_room(room):
    "{canonical_name} is located in {building}, {floor} (Room {room_number}).
     {landmarks}"

  _format_locate_multiple(result):
    "Found {count} {type}s:
     1. {name} (Room {number}) - {building}, {floor}
     2. ..."

  _format_nearest(result):
    "The nearest {type} to {reference} is {name}, located {proximity}
     in {building}, {floor} (Room {number})."

  _format_count(result):
    "There are {count} {description} matching your criteria."

  _format_list(result):
    "{EntityType} ({count}):
     - {name1}
     - {name2}
     ..."

Structural Proximity Algorithm:

  def find_nearest(reference: Room, target_type: RoomType, limit: int):
      # Tier 0: Same Floor
      candidates = rooms_by_building_floor[(ref.building_id, ref.floor_level)]
      matches = [r for r in candidates if r.room_type == target_type]
      if matches:
          return matches[:limit]

      # Tier 1: Same Building, Different Floor
      candidates = rooms_by_building[ref.building_id]
      matches = [r for r in candidates
                 if r.room_type == target_type and r.floor_id != ref.floor_id]
      if matches:
          # Sort by floor proximity
          matches.sort(key=lambda r: abs(r.floor_level.value - ref.floor_level.value))
          return matches[:limit]

      # Tier 2: Same Campus, Different Building
      candidates = rooms_by_campus[ref.campus_id]
      matches = [r for r in candidates
                 if r.room_type == target_type and r.building_id != ref.building_id]
      if matches:
          return matches[:limit]

      # Tier 3: Different Campus (fallback)
      all_rooms = get_all_active_rooms()
      matches = [r for r in all_rooms
                 if r.room_type == target_type and r.campus_id != ref.campus_id]
      return matches[:limit]

  # CQE Fast Path in process_query()

      structured_result = self._try_campus_query_engine(query)
      if structured_result and structured_result.matched:
          return OrchestratedResponse(
              answer=structured_result.formatted_response,
              mode=ResponseMode.STRUCTURED_AUTHORITATIVE,
              confidence_level="High",
              confidence_score=100.0,
              grounding_mode="index",
              extractor_used="campus_query_engine"
          )

  # New method
  def _try_campus_query_engine(self, query: str) -> StructuredQueryOutput:
      parsed_query = parse_campus_query(query)
      index = get_campus_index()
      executor = CampusQueryExecutor(index)
      result = executor.execute(parsed_query)
      formatted = format_query_result(result)
      return StructuredQueryOutput(
          matched=True,
          formatted_response=formatted,
          query_intent=parsed_query.intent.value,
          entity_count=len(result.entities),
          execution_mode=result.execution_mode
      )

8. ACADEMIC JUSTIFICATIONS
================================================================================

8.1 Why Hierarchical Over Flat Model?
-------------------------------------
| Criterion            | Flat Model        | Hierarchical Model       |
|----------------------|-------------------|--------------------------|
| Query Expressiveness | O(n) scan         | O(1) index lookup        |
| Structural Proximity | Undefined         | Natural distance         |
| Determinism          | Ambiguous         | Unambiguous containment  |
| Extensibility        | Schema changes    | Add entities easily      |

8.2 Why Structural Over Geometric Proximity?
--------------------------------------------
| Factor              | Geometric          | Structural               |
|---------------------|--------------------|--------------------------|
| Data Required       | GPS coordinates    | Already in schema        |
| User Mental Model   | Abstract distance  | "Same floor" thinking    |
| Determinism         | Path algorithm     | Absolute containment     |
| Implementation      | Floor plans needed | Index lookups only       |

8.3 Why JSON Over SQLite?
-------------------------
| Criterion           | JSON               | SQLite                   |
|---------------------|--------------------|--------------------------|
| Dependencies        | Zero (stdlib)      | sqlite3 library          |
| Current Scale       | 220 entities       | Overkill                 |
| Index Structures    | Already in code    | Would need new schema    |
| RPi Deployment      | Single file copy   | Database management      |
| Admin Updates       | Batch CSV imports  | Optimized for writes     |

Migration Triggers (future):
- Entity count > 1,000
- Complex join queries needed
- Concurrent write access required
- Historical versioning needed
