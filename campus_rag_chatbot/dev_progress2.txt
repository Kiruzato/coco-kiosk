OVERVIEW
================================================================================

Phase 6 introduces a dual-mode answering system that allows the chatbot to:
1. Answer campus-specific questions using RAG (Retrieval-Augmented Generation)
2. Answer general knowledge questions without document retrieval
3. Ask for clarification when query intent is unclear

This enhancement maintains strict safety guarantees while expanding the chatbot's
capabilities beyond campus information.

1. INTENT CLASSIFICATION FUNCTION
---------------------------------
Function: classify_intent(query: str, llm: ChatOpenAI)
Location: intent_classifier.py, lines 47-113

HOW IT WORKS:
- Takes user query and LLM instance as input
- Sends classification prompt to gpt-3.5-turbo
- Prompt asks LLM to classify into: CAMPUS, GENERAL, or AMBIGUOUS
- Parses LLM response and returns QueryIntent enum + metadata

CLASSIFICATION LOGIC:
- CAMPUS: Questions about Springfield University campus (library, parking,
  dining, services, policies, hours, locations)
  Examples: "library hours?", "where is parking?", "dining hall menu?"

- GENERAL: Questions not requiring campus documents (math, facts, definitions,
  greetings)
  Examples: "what is 15 * 23?", "hello", "capital of France?",
  "what is photosynthesis?"

- AMBIGUOUS: Unclear or vague questions needing more context
  Examples: "hours", "services", "help", "where is it?"

DEFAULT BEHAVIOR:
- If classification is unclear, defaults to CAMPUS for safety
- This prevents general mode from accidentally answering campus questions

METADATA RETURNED:
{
    "intent": "campus" | "general" | "ambiguous",
    "reasoning": "Why this intent was chosen",
    "raw_classification": "Raw LLM response",
    "query_length": int
}


2. SAFETY CHECK FUNCTION
------------------------
Function: safety_check_general_mode(query: str)
Location: intent_classifier.py, lines 116-133

HOW IT WORKS:
- Secondary safety layer using keyword matching
- Checks if query contains campus-related keywords
- Used to catch misclassified campus questions in general mode

CAMPUS KEYWORDS CHECKED:
"library", "dining", "parking", "campus", "student", "university",
"springfield", "building", "hours", "employment", "wifi", "it services",
"meal plan", "registration", "housing", "event", "facility", "gym",
"rec center", "academic", "advisor", "dorm", "residence", "tuition",
"financial aid"

SAFETY MECHANISM:
- If ANY campus keyword found → return is_safe: False
- General mode handler checks this and redirects to campus mode
- Prevents general mode from answering campus-specific questions


3. CAMPUS QUERY HANDLER
-----------------------
Function: handle_campus_query(query, session_id, memory, intent_metadata)
Location: app.py, lines 248-366

HOW IT WORKS:
This is the EXISTING RAG pipeline extracted into a dedicated function:

Step 1: Vector Retrieval
- Searches vector store for similar document chunks
- Uses similarity_search_with_relevance_scores()
- Retrieves top 4 chunks with score ≥ 0.5

Step 2: Confidence Scoring
- Computes confidence based on similarity scores
- Uses compute_confidence_score() from confidence_scorer.py
- Returns: HIGH, MEDIUM, or LOW confidence level

Step 3: Grounding Validation
- Checks if confidence meets minimum threshold (MEDIUM)
- If too low → REJECT with refusal message
- If acceptable → proceed to answer generation

Step 4: Answer Generation (if confidence is sufficient)
- Creates ConversationalRetrievalChain with:
  * LLM: gpt-3.5-turbo (temperature=0)
  * Retriever: Vector store with similarity threshold
  * Memory: Last 5 conversation turns
  * Prompt: Strict campus-only instructions
- Chain automatically:
  * Uses conversation history for follow-up questions
  * Generates answer from retrieved context
  * Returns source documents used

Step 5: Source Extraction
- Extracts document names, sections, chunk IDs from sources
- Deduplicates sources to avoid showing same chunk twice

Step 6: Logging
- Logs complete interaction with intent="campus", mode_used="campus"
- Includes retrieval results, confidence metrics, answer, sources

Step 7: Return Response
- Returns ChatResponse with:
  * Answer from RAG pipeline
  * Sources cited
  * Confidence level and score
  * mode="campus" for transparency


4. GENERAL QUERY HANDLER
------------------------
Function: handle_general_query(query, session_id, memory, intent_metadata)
Location: app.py, lines 369-428

HOW IT WORKS:
This is a NEW function that handles queries without document retrieval:

Step 1: Safety Check
- Calls safety_check_general_mode(query)
- If campus keywords detected → REDIRECT to handle_campus_query()
- This prevents answering campus questions in general mode

Step 2: Direct LLM Call (no retrieval)
- Creates prompt with safety instructions
- Prompt tells LLM to refuse if question is actually about campus
- Calls llm.invoke() directly (bypasses RAG pipeline)
- No document retrieval, no similarity search

Step 3: Memory Update
- Manually saves Q&A to conversation memory
- Uses memory.save_context({"question": query}, {"answer": answer})

Step 4: Transparency Label
- Adds "[Based on general AI knowledge]" to end of answer
- Makes it clear this is NOT from campus documents

Step 5: Logging
- Calls log_general_interaction() (new logging method)
- Logs with intent="general", mode_used="general"
- Sets retrieval_performed=False

Step 6: Return Response
- Returns ChatResponse with:
  * Answer with transparency label
  * sources=[] (no sources for general knowledge)
  * confidence_level="N/A" (no retrieval confidence)
  * mode="general" for transparency


5. AMBIGUOUS QUERY HANDLER
--------------------------
Function: handle_ambiguous_query(query, session_id, intent_metadata)
Location: app.py, lines 431-467

HOW IT WORKS:
This is a NEW function that asks for clarification:

Step 1: Create Clarification Message
- Explains the two modes available (campus vs general)
- Provides helpful examples for each mode
- Guides user to rephrase their question

CLARIFICATION MESSAGE:
"I'm not sure if you're asking about:
1. **Springfield University campus information** (library, dining, parking,
   campus services, etc.)
2. **General knowledge** (math, facts, definitions)

Could you please clarify? For example:
- 'What are the library hours?' → Campus information
- 'What is 15 + 27?' → General knowledge"

Step 2: Logging
- Calls log_ambiguous_interaction() (new logging method)
- Logs the clarification message shown to user
- Sets intent="ambiguous", mode_used="clarification"

Step 3: Return Response
- Returns ChatResponse with:
  * Clarification message as answer
  * sources=[] (no retrieval)
  * confidence_level="N/A"
  * mode="clarification" for transparency

Note: Ambiguous queries do NOT save to conversation memory


6. MODIFIED CHAT ENDPOINT
-------------------------
Function: chat(request: ChatRequest)
Location: app.py, lines 474-509

HOW IT WORKS:
The main endpoint now uses INTENT CLASSIFICATION and ROUTING:

OLD FLOW (Before Phase 6):
User Query → Retrieval → Confidence → Answer/Reject

NEW FLOW (Phase 6):
User Query → Intent Classification → Route by Intent → Mode-Specific Handler

Step 1: Session Management (unchanged)
- Get or create session with UUID
- Load conversation memory
- Update activity timestamp

Step 2: Query Validation (unchanged)
- Trim and check if query is empty
- Return 400 error if empty

Step 3: INTENT CLASSIFICATION (NEW)
- Call classify_intent(query, llm)
- Returns: QueryIntent enum + metadata
- Takes ~1-2 seconds (LLM call)

Step 4: ROUTING BASED ON INTENT (NEW)
IF intent == QueryIntent.GENERAL:
    → Call handle_general_query()
    → Direct LLM, no retrieval
    → Return with mode="general"

ELIF intent == QueryIntent.AMBIGUOUS:
    → Call handle_ambiguous_query()
    → Show clarification message
    → Return with mode="clarification"

ELSE (QueryIntent.CAMPUS):
    → Call handle_campus_query()
    → RAG pipeline with strict grounding
    → Return with mode="campus"

Each handler returns a complete ChatResponse, no further processing needed.

================================================================================
SAFETY MECHANISMS
================================================================================

1. NO SILENT FALLBACK
---------------------
RULE: Campus queries with low confidence stay in campus mode

HOW IT WORKS:
- If intent=CAMPUS but confidence=LOW → REJECT in campus mode
- Does NOT switch to general mode as fallback
- Returns: "I don't have verified campus information..."
- mode="campus" even when rejected

EXAMPLE:
Query: "What is the spiritual meaning of the bell tower?"
→ Intent: CAMPUS (mentions campus feature)
→ Confidence: MEDIUM (documents mention bell tower but not spiritual meaning)
→ Response: "I don't have verified campus information to answer that question."
→ Mode: "campus" (stayed in campus mode, no fallback)


2. KEYWORD SAFETY CHECK
-----------------------
RULE: General mode double-checks for campus keywords

HOW IT WORKS:
- Before answering in general mode, check query for campus keywords
- If detected → REDIRECT to campus mode instead
- Prevents misclassified campus questions from being answered incorrectly

EXAMPLE:
Query: "Tell me about the campus library"
→ Intent: GENERAL (hypothetical misclassification)
→ Safety check finds: "campus" and "library" keywords
→ Action: Redirect to handle_campus_query()
→ Result: Answered correctly with campus documents
→ Mode: "campus" (redirected safely)


3. LLM SELF-CORRECTION
----------------------
RULE: General mode prompt includes safety instructions

PROMPT EXCERPT:
"IMPORTANT SAFETY RULE:
If this question is actually about Springfield University campus, respond with:
'I should answer campus-specific questions using verified documents.
Please ask me about campus information.'"

HOW IT WORKS:
- Even if safety check misses something, LLM can self-correct
- LLM recognizes campus questions and refuses to answer
- Tertiary safety layer


4. DEFAULT TO CAMPUS
-------------------
RULE: When intent classification is unclear, default to campus mode

CODE (intent_classifier.py, lines 102-105):
else:
    # Default to CAMPUS for safety
    intent = QueryIntent.CAMPUS
    reasoning = "Classification unclear, defaulting to campus mode for safety"

WHY:
- Campus mode is more restrictive (requires documents)
- Safer to over-classify as campus than to risk wrong general answer
- Campus mode will simply reject if documents don't have the answer

================================================================================
LIMITATIONS AND FUTURE ENHANCEMENTS
================================================================================

CURRENT LIMITATIONS:

1. General mode doesn't fully leverage conversation memory
   - Saves to memory but doesn't include history in prompt
   - Could be enhanced to pass chat history to LLM

2. Memory is not persistent
   - Stored in RAM only
   - Server restart = all conversations lost
   - Could add database persistence

3. Ambiguous queries don't save to memory
   - Clarification requests not stored in conversation history
   - Could save for better context awareness

4. Intent classification adds latency
   - Extra LLM call (~1-2 seconds)
   - Could implement caching for common queries

5. No support for interactive games
   - Rock paper scissors, trivia, etc. not implemented
   - Could extend general mode for interactive features

POTENTIAL ENHANCEMENTS:

- Add intent classification caching
- Implement persistent conversation storage (database)
- Enhance general mode with better context awareness
- Add support for multi-turn interactions and games
- Implement intent classification confidence thresholds
- Add user feedback on intent classification accuracy
- Create admin dashboard for monitoring intent distribution
