PROJECT OVERVIEW
================================================================================

The Campus Information Kiosk is an AI-powered chatbot web application that
provides students and visitors with accurate, verified information about
Springfield University. It uses Retrieval-Augmented Generation (RAG) technology
to answer questions based on official campus documents.

The system ensures answers are grounded in verified campus information and
includes confidence scoring to prevent hallucinations or inaccurate responses.

CORE FEATURES
================================================================================

1. INTELLIGENT QUESTION ANSWERING
   ---------------------------------
   What it is:
   - AI-powered chatbot that answers campus-related questions
   - Uses GPT-3.5-turbo language model with RAG architecture
   - Only provides answers based on verified campus documents

   How it works:
   - User submits a question through the web interface
   - System converts question to embedding using OpenAI embeddings
   - FAISS vector store retrieves the top 4 most relevant document chunks
   - Retrieved chunks are scored for similarity (0.0 - 1.0 scale)
   - If similarity is too low (< 0.5), retrieval is rejected
   - Relevant chunks are sent to GPT-3.5 as context
   - AI generates answer strictly from provided context
   - Response includes answer, sources, and confidence score

   Covered Topics:
   - Library hours and services
   - Dining options and meal plans
   - Parking and transportation
   - IT services and Wi-Fi
   - Student employment
   - Campus events and activities
   - Academic programs

   Technical Details:
   - Endpoint: POST /chat
   - Vector embedding model: text-embedding-ada-002
   - LLM: gpt-3.5-turbo (temperature=0 for consistency)
   - Chunk size: 500 characters with 50 character overlap
   - Top K retrieval: 4 chunks
   - Relevance threshold: 0.5 minimum similarity


2. CONFIDENCE SCORING SYSTEM
   ---------------------------
   What it is:
   - Automated quality assessment for every response
   - Three-tier confidence levels: High, Medium, Low
   - Numerical score from 0-100

   How it works:
   - Analyzes similarity scores from document retrieval
   - Calculates multiple metrics:
     * Average similarity across all retrieved chunks
     * Maximum similarity (best matching chunk)
     * Minimum similarity (worst matching chunk)
     * Score variance (consistency measure)
     * Number of chunks retrieved

   - HIGH Confidence (70-100):
     * Average similarity >= 0.75
     * At least 2 relevant chunks found
     * Low variance (<= 0.05) indicating consistent scores
     * At least one highly relevant chunk (>= 0.80)

   - MEDIUM Confidence (40-75):
     * Average similarity >= 0.55
     * At least 1 relevant chunk found
     * OR high max similarity even if average is lower

   - LOW Confidence (0-40):
     * Average similarity < 0.55
     * Insufficient relevant chunks
     * High variance in scores

   - Grounding Validation:
     * If confidence < Medium threshold, answer is rejected
     * User receives message asking to rephrase or try different topic
     * Prevents hallucinated or unreliable answers

   Technical Implementation:
   - Module: confidence_scorer.py
   - Thresholds configurable in code
   - Returns both level (enum) and numerical score


3. CONVERSATION MEMORY
   --------------------
   What it is:
   - Session-based conversation tracking
   - Maintains context across multiple questions
   - Enables follow-up questions and clarifications

   How it works:
   - Each user gets a unique session ID (UUID)
   - System stores last 5 conversation turns per session
   - Memory uses ConversationBufferWindowMemory from LangChain
   - When user asks follow-up, previous context helps interpretation
   - Sessions auto-expire after 30 minutes of inactivity
   - Cleanup runs automatically before creating new sessions

   Example:
   - User: "What are the library hours?"
   - Bot: [provides library hours]
   - User: "What about during finals?" (follow-up understood via memory)
   - Bot: [provides extended finals hours]

   Technical Details:
   - In-memory storage (dict-based)
   - Session timeout: 30 minutes
   - Memory window: 5 conversation turns
   - Memory key: "chat_history"
   - Session ID persists across multiple queries


4. SOURCE CITATION
   ----------------
   What it is:
   - Transparent attribution for all answers
   - Shows which documents were used to generate response
   - Builds trust and allows verification

   How it works:
   - System tracks which document chunks were retrieved
   - Extracts metadata from each chunk:
     * Document name (e.g., "campus_info.txt")
     * Section name (e.g., "Library Hours and Services")
     * Chunk ID (position in document)
   - Displays up to 4 sources per response
   - Deduplicates sources to avoid repetition

   Display Format:
   - Document name - Section name
   - Example: "campus_info.txt - Library Hours and Services"

   Technical Details:
   - Metadata stored with each vector embedding
   - Retrieved alongside document content
   - Returned in ChatResponse model


5. USER FEEDBACK SYSTEM
   ----------------------
   What it is:
   - Thumbs up/down rating for each response
   - Optional comment field
   - Used to improve system over time

   How it works:
   - After each non-rejected answer, feedback buttons appear
   - User clicks "Yes, helpful" or "Not helpful"
   - Feedback sent to backend via POST /feedback
   - Data logged to feedback.jsonl in JSON Lines format
   - Each entry includes:
     * Session ID
     * Query ID
     * Helpful (true/false)
     * Optional comment
     * Timestamp
   - After submission, buttons replaced with "Thank you" message

   Data Collection:
   - File: logs/feedback.jsonl
   - Format: JSON Lines (one JSON object per line)
   - Can be analyzed to identify problematic queries

   Technical Details:
   - Endpoint: POST /feedback
   - No authentication required
   - Fire-and-forget (no error shown to user if fails)


6. CONVERSATION RESET
   --------------------
   What it is:
   - Ability to start fresh conversation
   - Clears chat history and memory

   How it works:
   - User clicks "Start New Conversation" button
   - Confirmation dialog appears
   - If confirmed, frontend sends POST /reset with session ID
   - Backend deletes session from memory
   - Frontend clears chat UI (keeps welcome message)
   - Next query creates new session ID

   Technical Details:
   - Endpoint: POST /reset
   - Session removed from in-memory dict
   - No database cleanup needed


7. QUERY LOGGING SYSTEM
   ----------------------
   What it is:
   - Comprehensive logging of all interactions
   - Enables debugging, analysis, and system improvement
   - Three separate log files for different aspects

   How it works:
   - Every query triggers logging at multiple stages:

   A) Query Log (queries.jsonl):
      - User's original question
      - Session ID
      - Timestamp
      - Query ID (for correlation)

   B) Retrieval Log (retrieval.jsonl):
      - Query ID
      - Retrieved chunks with previews
      - Similarity scores for each chunk
      - Average, max, min similarity
      - Number of chunks retrieved
      - Retrieval parameters (k, threshold)

   C) Response Log (response.jsonl):
      - Query ID
      - Generated answer
      - Confidence level and metrics
      - Sources used
      - Answer length
      - Generation parameters

   - All logs use JSON Lines format for easy parsing
   - Query ID ties all three logs together
   - Format: YYYYMMDD_HHMMSS_microseconds

   Technical Implementation:
   - Module: query_logger.py
   - Log directory: logs/
   - Automatic directory creation
   - UTF-8 encoding for international characters
   - Custom JSON serializer handles numpy types (fixed bug)


8. DOCUMENT MANAGEMENT SYSTEM
   ---------------------------
   What it is:
   - Admin CLI for managing knowledge base documents
   - Track what documents are ingested
   - Version control via file hashing

   How it works:

   A) Document Ingestion (admin.py ingest):
      - Accepts files or directories
      - Supported formats: .txt, .pdf, .md
      - Computes SHA-256 hash of each file
      - Checks for duplicates via hash comparison
      - Splits text into 500-character chunks (50 char overlap)
      - Generates embeddings for each chunk
      - Stores in FAISS vector database
      - Updates document_registry.json

   B) Document Registry (document_registry.json):
      - JSON file tracking all ingested documents
      - Stores for each document:
        * Unique document ID
        * Filename and file path
        * File type (.txt, .pdf, etc.)
        * File hash (SHA-256)
        * Number of chunks created
        * Chunk size and overlap settings
        * Ingestion timestamp

   C) Vector Store:
      - FAISS index for fast similarity search
      - Stored in vector_store/ directory
      - Uses AVX2 optimization for speed
      - Pickle format for Python compatibility

   D) Admin Commands:
      - list: Show all ingested documents
      - ingest: Add new documents
      - delete: Remove document from system
      - rebuild: Recreate vector store from registry
      - info: Show detailed document information

   Current Knowledge Base:
   - academic_programs.txt (34 chunks)
   - campus_info.txt (20 chunks)
   - events_activities.txt (29 chunks)
   - Total: 3 documents, 83 chunks

   Technical Details:
   - Module: document_manager.py
   - CLI: admin.py
   - Vector DB: FAISS
   - Embedding: text-embedding-ada-002 (OpenAI)

Bug #1: JSON Serialization Error (FIXED)
-----------------------------------------
Date: 2026-01-04
Issue: POST /chat endpoint returning 500 Internal Server Error
Cause: Numpy float32 objects from FAISS similarity scores not JSON serializable
Error: "TypeError: Object of type float32 is not JSON serializable"

Solution:
1. Added numpy import to query_logger.py
2. Created custom JSON serialization handler
3. Converts numpy.float32/int32 to Python float/int
4. Applied to _append_to_log() method
5. Also converted float values in log_retrieval() explicitly

Files Modified:
- query_logger.py (lines 11, 124, 140-143, 260-266)

Code Changes:
- Added: import numpy as np
- Modified similarity score handling:
  * round(float(score), 4) instead of round(score, 4)
- Added JSON serialization handler:
  def convert_to_json_serializable(obj):

          return float(obj)

================================================================================
KNOWN LIMITATIONS
================================================================================

1. In-Memory Sessions
   - Sessions lost on server restart
   - Not suitable for horizontal scaling
   - Consider Redis or database for production

2. No User Authentication
   - Public access (appropriate for kiosk)
   - No rate limiting
   - Could be abused

3. Limited Document Formats
   - Only .txt, .pdf, .md supported
   - No Word docs (.docx)
   - No HTML parsing

4. Static Knowledge Base
   - Documents must be manually ingested
   - No automatic updates
   - No web scraping capability

5. Single Language
   - English only
   - No internationalization

6. OpenAI Dependency
   - Requires internet connection
   - Subject to API rate limits
   - Monthly API costs

7. No Analytics Dashboard
   - Logs are JSON files, not visualized
   - No built-in reporting
   - Manual analysis required

8. Deprecated API Usage
   - Uses on_event decorators (LangChain deprecation warnings)
   - Should migrate to lifespan handlers
   - ConversationBufferWindowMemory deprecated
