Phase 17A Changes Report
========================
Date: January 26, 2026

OVERVIEW
--------
This report documents the changes made in Phase 17A (iterations 13 through 13.3)
to implement retrieval-first routing and fix keyword scoring issues.


ITERATION 13 - Phase 17A: Hybrid Retrieval & Grounding Validation
-----------------------------------------------------------------
Problem: Semantic neighbor confusion - queries like "Dean's Lister requirements"
         were returning content about "Team Leadership Award" due to semantic
         similarity in vector space.

Solution: Implemented hybrid retrieval combining vector similarity with BM25
          keyword matching.

Changes:
- Created retrieval_validator.py with:
  * extract_query_terms() - filters stopwords from queries
  * compute_keyword_scores() - BM25 scoring for keyword matching
  * combine_hybrid_scores() - weighted combination (0.7 vector + 0.3 keyword)
  * validate_grounding() - ensures query terms appear in retrieved chunks

- Added GROUNDING_FAILED event type to event_tracker.py for observability


ITERATION 13.1 - Phase 17A.1: Developer RAG-Only Mode
-----------------------------------------------------
Problem: Developers needed a way to test RAG retrieval without general AI
         fallback interfering.

Solution: Added a toggle at /dev page to enable RAG-only mode.

Changes:
- Created static/dev.html - Developer tools page with toggle switch
- Created static/dev.js - JavaScript for toggle functionality
- Added rag_only_mode flag to app.py
- Added /dev/rag-only-mode endpoint for toggling
- Added /dev/status endpoint for checking current mode
- Added RAG_MODE_CHANGED event type for logging


ITERATION 13.2 - Phase 17A.2: Retrieval-First Routing
-----------------------------------------------------
Problem: Intent-first routing was too strict. Queries like "how to attain
         honorable mention?" were classified as GENERAL instead of CAMPUS
         unless the user added explicit keywords like "in this school".

Solution: Replace intent-first routing with retrieval-first routing. Always
          attempt document retrieval before deciding to use general AI.

Changes:
- Created attempt_document_retrieval() function in app.py
- Added routing event types:
  * ROUTING_DOCUMENT_ATTEMPTED
  * ROUTING_DOCUMENT_SUCCESS
  * ROUTING_GENERAL_FALLBACK
- Modified handle_campus_query() to accept precomputed_retrieval parameter
- Restructured /chat endpoint routing logic:
  1. Check if directory query -> handle_directory_query()
  2. Attempt document retrieval FIRST
  3. If grounded AND confidence >= MEDIUM -> use RAG answer
  4. Else if RAG_ONLY_MODE -> refuse
  5. Else -> fall back to general AI


ITERATION 13.3 - Phase 17A.2.1: Fix Keyword Scoring
---------------------------------------------------
Problem #1: BM25's IDF normalization was penalizing queries that retrieved
            multiple relevant chunks. Query "how to attain honorable mention?"
            retrieved 2 good chunks but got LOW confidence (21.6), while
            "how to attain honorable mention in this school?" retrieved only
            1 good chunk but got MEDIUM confidence (70.1).

Problem #2: After fixing Problem #1, a regression occurred. Query "who is the
            dean of engineering department?" started failing because the new
            word boundary check was too strict (only checking for spaces).

Solution:
1. Replace BM25 with term coverage scoring (fraction of query terms found)
2. Use regex word boundaries (\b) instead of strict space matching

Changes to compute_keyword_scores() in retrieval_validator.py:

OLD (BM25-based):
- Used BM25Okapi for scoring
- Normalized by max score (caused IDF penalty issue)
- Checked word boundaries with spaces only

NEW (Term coverage-based):
- Computes coverage = matched_terms / total_terms
- Adds frequency bonus for multiple occurrences
- Uses regex \b for proper word boundary matching
- Handles terms followed by punctuation (e.g., "engineering," "dean.")
