================================================================================
DIRECTORY QUERY HANDLING ARCHITECTURE REPORT
================================================================================
Date: 2026-02-12
Project: CoCo Campus RAG Chatbot

This report explains how the chatbot processes and answers directory/location
queries (e.g., "Where is the library?", "How do I get to the canteen?").

================================================================================
1. OVERVIEW
================================================================================

Directory queries are handled through a specialized pipeline that prioritizes:
1. ACCURACY: No location details are invented or hallucinated
2. DETERMINISM: Same query always yields same answer
3. SAFETY: Strict grounding prevents false location information

The system uses a hybrid approach:
- PRIMARY: Entity Resolution (deterministic, instant, highest confidence)
- FALLBACK: RAG-based retrieval (when entity not found)

4. ENTITY REGISTRY
================================================================================

File: campus_rag_chatbot/entity_registry.py
Data: campus_rag_chatbot/directory_entities.json

DirectoryEntity Data Class:
---------------------------
@dataclass
class DirectoryEntity:
    entity_id: str           # Unique ID (e.g., "CANTEEN", "LIBRARY")
    canonical_name: str      # Official name (e.g., "Main Library")
    aliases: List[str]       # Alternative names (e.g., ["lib", "library"])
    building: str            # Building name
    floor: str               # Floor level (e.g., "Ground Floor")
    room: Optional[str]      # Room number if applicable
    campus: str              # Campus name
    department: Optional[str] # Department (optional)
    landmarks: Optional[str] # Navigation hints
    description: Optional[str]
    status: str              # "active" or "inactive"
    last_updated: Optional[str]

EntityRegistry Class:
---------------------
- Loads entities from JSON file at startup
- Builds O(1) alias index for fast lookup
- Case-insensitive matching
- Supports partial/fuzzy matching for disambiguation

Key Methods:
- get_by_alias(alias) -> DirectoryEntity or None
- get_active_entities() -> List[DirectoryEntity]
- find_matching_entities(query) -> List[DirectoryEntity] (for disambiguation)

================================================================================
5. ENTITY RESOLUTION
================================================================================

File: campus_rag_chatbot/entity_resolver.py

Step 1: Extract Subject
-----------------------
Function: extract_subject(canonical_query) -> str

Examples:
  "library location" -> "library"
  "room sp303 location" -> "sp303"
  "canteen location" -> "canteen"

Step 2: Resolve Entity
----------------------
Function: resolve_entity(subject, registry) -> (entity, confidence, method)

Resolution Strategy (priority order):
1. Exact match on canonical_name (case-insensitive)
2. Exact match on any alias (case-insensitive)

Returns:
  - entity: DirectoryEntity or None
  - confidence: 1.0 for exact match, 0.0 for no match
  - method: "exact_canonical", "exact_alias", or "none"

Step 3: Format Response
-----------------------
Function: format_entity_response(entity) -> str

Template-based, deterministic response generation:

Example Output:
"The Main Library is located in the Academic Building, 2nd Floor.
It is accessible via the main staircase near the entrance lobby."

Components included:
  - Canonical name
  - Building
  - Floor
  - Room (if applicable)
  - Landmarks (navigation hints)

7. DISAMBIGUATION (PHASE 14)
================================================================================

File: campus_rag_chatbot/app.py
Function: handle_entity_disambiguation() (lines 1847-1920)

When multiple entities match a query (e.g., "court" matches both
"Basketball Court" and "Tennis Court"):

1. DETECTION:
   matching_entities = entity_registry.find_matching_entities(subject)
   if len(matching_entities) > 1:
       return handle_entity_disambiguation(...)

2. PRESENTATION:
   Response format:
   "I found multiple locations that might match. Which one do you mean?

   1. Basketball Court (Sports Complex)
   2. Tennis Court (Outdoor Area)
   3. Moot Court (Law Building)

   Please reply with the number or name."

3. STATE STORAGE:
   session["conversation_context"]["awaiting_disambiguation"] = True
   session["conversation_context"]["disambiguation_candidates"] = [entity_ids]

4. SELECTION HANDLING:
   User can reply with:
   - Number: "1", "2", "3"
   - Position word: "first", "second", "third"
   - Partial name: "basketball", "tennis"

9. RAG FALLBACK
================================================================================

When entity resolution fails, the system falls back to RAG retrieval:

Step 1: Vector Search
---------------------
retrieval_results = doc_manager.vector_store.similarity_search_with_relevance_scores(
    canonical_query,
    k=8,  # Top 8 chunks
    score_threshold=0.5
)

Step 2: Confidence Scoring
--------------------------
confidence_level, metrics = compute_confidence_score(similarity_scores)

For directory queries, ONLY HIGH confidence is accepted.
MEDIUM confidence is rejected with:
  "I don't have precise location information for that yet."

Step 3: Entity Agreement Check
------------------------------
If MEDIUM confidence, check if multiple chunks agree on same entity:
  has_agreement, common_entity, entities = check_entity_agreement(docs, scores)

If agreement found, may promote to HIGH confidence.

Step 4: LLM Generation (if HIGH)
--------------------------------
Uses specialized directory prompt:

CRITICAL RULES FOR LOCATION QUESTIONS:
1. ONLY provide location information EXPLICITLY stated in context
2. May ONLY mention: building names, floor numbers, room numbers from context
3. If exact location not stated, respond: "I don't have precise info..."
4. NEVER guess or invent buildings, floors, rooms, or directions
5. Always mention the source (e.g., "According to the Campus Directory...")

================================================================================
10. CONFIDENCE REQUIREMENTS
================================================================================

Directory queries have STRICTER confidence requirements:

| Query Type      | Minimum Confidence | Fallback Behavior |
|-----------------|-------------------|-------------------|
| General Campus  | MEDIUM            | LLM generates     |
| Directory       | HIGH              | REJECT            |

Confidence Levels:
- HIGH: >= 0.70 avg similarity, >= 0.78 max similarity
- MEDIUM: >= 0.50 avg similarity
- LOW: < 0.50 avg similarity

Rejection Message:
"I don't have precise location information for that yet. Please check
with the campus information desk or security office for assistance."

================================================================================
14. SAFETY GUARANTEES
================================================================================

1. NO HALLUCINATION:
   - Entity resolution is deterministic (template-based)
   - LLM fallback has strict grounding rules
   - Cannot invent buildings, floors, or room numbers

2. HIGH CONFIDENCE REQUIRED:
   - Directory queries require HIGH confidence
   - Low-confidence answers are rejected, not guessed

3. SOURCE ATTRIBUTION:
   - LLM responses must cite source documents
   - Entity responses come from verified registry

4. INACTIVE ENTITY FILTERING:
   - Deactivated entities are excluded from resolution
   - Admin can hide locations without deleting data
