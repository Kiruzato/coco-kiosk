NEW FEATURES IMPLEMENTED
================================================================================

1. STANDARDIZED ERROR CODES (VoiceErrorCode Enum)
   -----------------------------------------------
   - SERVICE_UNAVAILABLE: Voice services not initialized
   - STT_UNAVAILABLE: STT service not available
   - TTS_UNAVAILABLE: TTS service not available
   - INVALID_AUDIO: Invalid audio file content
   - AUDIO_TOO_LARGE: Audio exceeds 10MB limit
   - AUDIO_TOO_LONG: Audio exceeds 60 second limit
   - EMPTY_AUDIO: Empty audio file
   - UNSUPPORTED_FORMAT: Unsupported audio format
   - TRANSCRIPTION_FAILED: STT processing failed
   - SYNTHESIS_FAILED: TTS processing failed
   - NO_SPEECH_DETECTED: No speech in audio
   - LOW_CONFIDENCE: Transcription confidence below threshold
   - RATE_LIMITED: Too many requests
   - AUDIO_NOT_FOUND: Audio ID not found or expired
   - TEXT_REQUIRED: Empty text for TTS
   - TEXT_TOO_LONG: Text exceeds 2000 character limit

2. RATE LIMITING
   --------------
   Per-client rate limits (per minute):
   - /voice/transcribe: 30 requests
   - /voice/synthesize: 60 requests
   - /voice/chat: 20 requests

   Client identification:
   - Uses X-Forwarded-For header if behind proxy
   - Falls back to client IP address
   - 60-second sliding window

3. HEALTH MONITORING ENDPOINT (/voice/health)
   -------------------------------------------
   Returns:
   - Overall status: healthy | degraded | unhealthy
   - Component status: STT, TTS, orchestrator, audio_storage
   - Request metrics: counts per endpoint (success/error)
   - Storage metrics: entries, size, expired count
   - Uptime: seconds since startup
   - Version: "33.0"

   Example response:
   {
     "status": "degraded",
     "voice_enabled": true,
     "components": {
       "stt": {"status": "unavailable", "available": false, "engine": "whisper.cpp"},
       "tts": {"status": "unavailable", "available": false, "engine": "piper"},
       "orchestrator": {"status": "healthy", "available": true},
       "audio_storage": {"status": "healthy", "current_entries": 0}
     },
     "metrics": {...},
     "uptime_seconds": 14.22,
     "version": "33.0"
   }

4. WEBSOCKET STREAMING (/voice/stream)
   ------------------------------------
   Protocol:
   - Client connects and sends audio chunks as binary messages
   - Server sends back JSON messages with status/results
   - Client sends "END" text message when done recording
   - Client can send "CANCEL" to abort, "PING" for keepalive

   Message types from server:
   - connected: Session ID assigned
   - receiving: Acknowledgment of chunks received
   - processing: Transcription in progress
   - final: Transcription result
   - error: Error occurred
   - cancelled: Recording cancelled

5. AUDIO VALIDATION
   -----------------
   Format detection via magic bytes:
   - WAV (RIFF header)
   - WebM (EBML header)
   - MP3 (ID3 or frame sync)
   - OGG (OggS header)
   - FLAC (fLaC header)

   Security checks:
   - Size limit: 10MB
   - Embedded script detection (<script, javascript:, data:text/html)
   - Format validation before processing

6. REQUEST METRICS
   ----------------
   Tracked per endpoint:
   - transcribe_count, transcribe_success, transcribe_errors
   - synthesize_count, synthesize_success, synthesize_errors
   - chat_count, chat_success, chat_errors

   Storage metrics:
   - total_stored, total_retrieved, total_expired
