OVERVIEW
================================================================================

Phase 32 implements the voice infrastructure for the CoCo campus kiosk,
enabling speech-to-text (STT) and text-to-speech (TTS) capabilities.

Key Design Principle:
    Voice is a MODALITY LAYER, not a decision layer.
    All RAG guarantees (grounding, confidence, determinism) are preserved.
    Voice just handles I/O transformation (audio <-> text).

API ENDPOINTS
================================================================================

GET  /voice/status          Check voice service availability
POST /voice/transcribe      Transcribe audio to text (STT)

================================================================================
CONFIGURATION
================================================================================

Environment Variables:
    VOICE_ENABLED           Enable/disable voice features (default: true)
    WHISPER_MODEL_PATH      Path to Whisper.cpp model file
    PIPER_MODEL_PATH        Path to Piper TTS model file
    WHISPER_THREADS         Number of CPU threads for Whisper (default: 4)
    WHISPER_CLOUD_FALLBACK  Enable cloud fallback for low confidence
    STT_MIN_CONFIDENCE      Minimum confidence threshold (default: 0.7)
    TTS_MAX_CHARS           Maximum characters for TTS (default: 500)

================================================================================
KEY FEATURES
================================================================================

1. Offline-First Design
   - Primary STT: Whisper.cpp (ARM64 NEON optimized for RPi5)
   - Primary TTS: Piper (ONNX neural network voices)
   - No internet required for basic operation

2. Automatic Fallback
   - Low confidence STT -> retry with cloud API
   - Primary engine failure -> use fallback engine
   - TTS failure -> text response still available

3. Confidence-Based Routing
   - Confidence threshold: 0.7
   - Low confidence triggers text input fallback prompt
   - Preserves user intent even with poor audio quality

4. Temporary Audio Storage
   - TTS audio stored with 5-minute TTL
   - Auto-cleanup of expired entries
   - Maximum 100 entries to limit memory usage

5. Voice Event Logging
   - Integrated with existing EventTracker
   - Tracks: STT success/confidence, chat success, TTS success
   - Latency metrics for each phase

================================================================================
TECHNOLOGY STACK
================================================================================

Speech-to-Text (STT):
    Primary:  Whisper.cpp (tiny.en model, ~75MB)
    Fallback: OpenAI Whisper API (cloud)

Text-to-Speech (TTS):
    Primary:  Piper TTS (en_US-amy-medium voice, ~63MB)
    Fallback: espeak-ng (system package)

Audio Formats:
    Input:  WAV, WebM, MP3, OGG (auto-detected)
    Output: WAV (16-bit PCM)

================================================================================
MODEL INSTALLATION (Required for Voice to Work)
================================================================================

1. Whisper.cpp (STT):
   git clone https://github.com/ggerganov/whisper.cpp
   cd whisper.cpp
   make -j4
   ./models/download-ggml-model.sh tiny.en

   Copy ggml-tiny.en.bin to:
   campus_rag_chatbot/voice/models/whisper/

2. Piper TTS:
   pip install piper-tts
   Download voice model from:
   https://github.com/rhasspy/piper/releases

   Copy .onnx and .onnx.json files to:
   campus_rag_chatbot/voice/models/piper/

3. espeak-ng (fallback):
   Windows: Download from https://github.com/espeak-ng/espeak-ng/releases
   Linux:   sudo apt-get install espeak-ng
