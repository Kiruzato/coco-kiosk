OVERVIEW
================================================================================

Phase 39 implements two major features for the CoCo campus RAG chatbot:

1. Phase 39A: Admin-Configurable Cloud Credentials
   - Secure encrypted credential storage (AES-256-GCM with PBKDF2)
   - Admin UI input forms for OpenAI API key and Google Cloud service account
   - Credentials persist across restarts and apply to environment at startup
   - Verify button to test credentials without saving

2. Phase 39B: Real-Time Debugging Panel
   - Debug panel in chatbot UI showing per-request service usage
   - Admin toggle to enable/disable debug visibility for all users
   - Displays: LLM provider, retrieval stats, grounding status, timing

================================================================================
FEATURE 1: ADMIN-CONFIGURABLE CLOUD CREDENTIALS (Phase 39A)
================================================================================

Storage Approach: Encrypted JSON File
-------------------------------------
- AES-256-GCM authenticated encryption
- PBKDF2 key derivation (100,000 iterations) from admin password
- Atomic file writes (temp file + rename) for data safety
- File: data/credentials.enc

Schema:
{
  "version": 1,
  "credentials": {
    "openai_api_key": {
      "value": "sk-...",
      "updated_at": "2026-02-07T10:30:00Z"
    },
    "google_cloud_credentials": {
      "type": "service_account_json",
      "value": { ...service account JSON... },
      "updated_at": "2026-02-07T10:30:00Z"
    }
  }
}

API Endpoints:
- GET  /admin/voice/credentials/status  - Get credential status (existing)
- POST /admin/voice/credentials         - Save encrypted credential
- POST /admin/voice/credentials/verify  - Test credential without saving

Admin UI:
- OpenAI API Key input with show/hide toggle
- Google Cloud JSON file upload
- Save and Verify buttons for each credential type
- Status badges (Configured, Valid, Invalid)
- Last updated timestamp display

Live Reload Flow:
1. On startup: CredentialManager.apply_to_environment() loads creds to os.environ
2. On save: Encrypt -> Write file -> Update os.environ -> Reload services
3. No server restart required

FEATURE 2: REAL-TIME DEBUGGING PANEL (Phase 39B)
================================================================================

DebugInfo Schema:
-----------------
class DebugInfo(BaseModel):
    # Provider info
    llm_provider: str = "openai"
    llm_model: str = "gpt-3.5-turbo"

    # Voice info (if applicable)
    stt_engine: Optional[str] = None
    stt_fallback_used: bool = False
    tts_engine: Optional[str] = None
    tts_fallback_used: bool = False

    # Retrieval info
    retrieval_mode: str = "hybrid"
    retrieval_method: str = "rrf"
    chunks_retrieved: int = 0
    top_chunk_score: float = 0.0

    # Routing info
    intent_classified: str = ""
    routing_path: str = ""

    # Grounding info
    query_terms: List[str] = []
    grounding_passed: bool = True
    grounding_mode: str = "keyword"
    matched_terms: List[str] = []

    # Timing (ms)
    timing: Dict[str, float] = {}

    # Deterministic extractor
    extractor_used: Optional[str] = None

API Endpoints:
- GET  /admin/debug/status  - Get current debug mode state
- POST /admin/debug/toggle  - Enable/disable debug mode

Persistence:
- File: data/debug_settings.json
- Format: { "debug_enabled": false, "updated_at": "..." }

Admin UI (Developer Section):
- Toggle switch for debug panel visibility
- Descriptive text explaining what debug panel shows
- Note about visibility affecting all users

Chatbot UI Debug Panel:
- Collapsible panel below each assistant message
- 4-5 column grid layout:
  - PROVIDER: LLM model, provider name
  - RETRIEVAL: Mode, method, chunks, top score
  - ROUTING: Intent, path, grounding status
  - VOICE (optional): STT/TTS engines, fallback usage
  - TIMING: Retrieval ms, LLM ms, total ms
- Query terms displayed as chips/badges
- Collapsed by default, expands on click

================================================================================
SECURITY CONSIDERATIONS
================================================================================

Credentials:
- AES-256-GCM encryption (authenticated encryption)
- PBKDF2 key derivation with 100,000 iterations
- File permissions: Rely on OS-level access control
- Admin-only access via verify_admin_session
- Never log actual credential values
- Validate format before saving (sk- prefix, valid JSON)
- Atomic writes prevent corruption

Debug Panel:
- No PII in debug info (technical metadata only)
- Admin-controlled toggle
- No credentials exposed in debug output
