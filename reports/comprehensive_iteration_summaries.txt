Iteration 1:
This initial phase established the core architecture for the campus Retrieval-Augmented Generation (RAG) system. The primary goal was to validate the feasibility of a localized information pipeline capable of ingesting diverse campus documentation and answering user queries. Development focused on the ingestion workflow, vector storage using FAISS, and the generation loop powered by a Large Language Model (LLM). This MVP (Minimum Viable Product) verified that a closed-domain knowledge base could successfully retrieve relevant content and synthesize answers, providing a proof-of-concept for the kiosk deployment.

Iteration 2:
This iteration addressed the critical issue of model hallucination to ensure response reliability. To transition from a prototype to a trustworthy system, we implemented a rigorous verification layer. The key development was a "grounding" protocol that validates whether generating answers are strictly supported by the retrieved context, coupled with a confidence scoring mechanism (High/Medium/Low). These additions transformed the system into a deterministic tool capable of self-assessing answer quality and refusing queries when sufficient evidence is unavailable.

Iteration 3:
We defined the operational boundaries of the system by implementing domain-specific routing logic. The goal was to constrain the model's broad general knowledge to the specific context of the campus environment. A classification layer was introduced to distinguish between "in-domain" campus queries and "out-of-domain" general inquiries. This architectural control ensured the system maintained its functional identity as a specialized wayfinding and policy assistant rather than acting as a generic conversational chatbot.

Iteration 4:
To support long-term maintenance, this phase focused on building administrative infrastructure. The requirement was to allow non-technical staff to manage the document corpus without engineering support. We developed a dedicated document management interface that enables dynamic uploading, deletion, and re-indexing of the knowledge base. This provided the necessary tools for sustainable content management in a production environment.

Iteration 5:
This phase resolved precision limitations in handling location-based queries. Standard probabilistic retrieval was found to be insufficient for strict directory and wayfinding tasks. We adopted a hybrid architecture by integrating a deterministic, structured entity registry alongside the vector system. This allowed the system to accurately resolve specific building and office queries using exact matching, thereby eliminating hallucination risks for static, high-stakes directory data.

Iteration 6:
The interaction model evolved from a stateless request-response pattern to a stateful conversational interface. Recognizing that users often ask follow-up questions dependent on previous context, we integrated a memory management module. This allowed the system to track conversation history and resolve anaphoric references (e.g., "What time does it close?"). This change significantly improved the naturalness of the user experience by supporting multi-turn dialogues.

Iteration 7:
We enhanced the dialogue management system to handle linguistic ambiguity and context shifts. Usage data indicated that users frequently provided vague queries or changed topics mid-conversation. We implemented a disambiguation framework to detect multiple potential entity matches and request clarification, as well as logic to detect topic changes. These features ensured that the conversational context remained accurate and responsive to the user's evolving intent.

Iteration 8:
This iteration focused on data-driven optimization through a new observability layer. To diagnose retrieval failures and measure system performance, we built comprehensive event tracking and analytics logging infrastructure. This provided granular visibility into query patterns, refusal rates, and retrieval latency, offering the empirical evidence needed to guide subsequent algorithmic refinements and validation steps.

Iteration 9:
We performed a major architectural overhaul to address limitations in vector-based semantic search. Identifying that vector embeddings occasionally missed exact keyword matches, we adopted a "Hybrid Retrieval" methodology. This fused vector similarity search with sparse keyword scoring (BM25) and enforced a strict "retrieval-first" pipeline. This ensured that the generative model relied exclusively on high-relevance, validated context, significantly improving recall for domain-specific terminology.

Iteration 10:
This phase focused on the deterministic extraction of structured lists from unstructured text. The system initially struggled with fragmentation when retrieving enumeration data (e.g., lists of faculty deans). We introduced "Entity-Centric Consolidation," which involved pre-computing synthetic text chunks to aggregate related entities, supported by a multi-stage text normalization pipeline. This methodology guaranteed that list-based answers were complete and consistent, overcoming the variance of standard chunking strategies.

Iteration 11:
We addressed retrieval challenges for long-form, semantic-heavy content such as policies and prayers. Strict keyword grounding was found to be too restrictive for this type of content. We introduced "Semantic Grounding," allowing high-similarity semantic matches to override keyword requirements, and a "Contiguous Context Reconstruction" mechanism to stitch adjacent text chunks together. These changes preserved narrative continuity and allowed the system to retrieve and recite full texts accurately.

Iteration 12:
This iteration prioritized system scalability and code modularity. As retrieval logic grew in complexity, we refactored consolidation and validation mechanisms into a generic, configuration-driven engine. We also introduced a metadata indexing layer to enable O(1) lookups for document attributes. These non-functional improvements reduced technical debt and optimized the efficiency of the retrieval pipeline, preparing the architecture for larger datasets.

Iteration 13:
We aimed for state-of-the-art retrieval relevance by upgrading the ranking algorithms. The previous linear scoring method was replaced with Reciprocal Rank Fusion (RRF), an industry-standard technique for combining disparate rank lists. We also integrated query expansion using domain-specific synonyms and result diversity filters. These enhancements improved the system's ability to handle vocabulary mismatch and ensured that search results were diverse and representative.

Iteration 14:
We expanded the system's domain capabilities by leveraging established deterministic patterns. Specialized extraction logic was developed for temporal events and office contact information. By processing these data types with dedicated pipelines similar to our entity work, the system achieved high precision in answering schedule and contact-related queries, further reducing reliance on the LLM for factual reference data.

Iteration 15:
The final architectural evolution introduced a multimodal voice interface. We integrated a modular "Voice Modality Layer" utilizing offline-first Speech-to-Text (STT) and Text-to-Speech (TTS) services. This required a new orchestration layer to manage latency and state transitions. This development transformed the text-based retrieval engine into a fully conversational vocal assistant suitable for physical kiosk deployment.
