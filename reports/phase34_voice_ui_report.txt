================================================================================
VOICE STATE MACHINE
================================================================================

States:
- IDLE: Default state, mic button ready
- LISTENING: Recording audio, green pulse animation
- PROCESSING: Sending audio to API, orange state
- RESPONDING: Playing TTS response, blue waveform animation
- ERROR: Error state with auto-clear after 3 seconds

Transitions:
- IDLE -> LISTENING: User clicks mic button
- LISTENING -> PROCESSING: User clicks again or auto-stop (30s)
- PROCESSING -> RESPONDING: If TTS audio available
- PROCESSING -> IDLE: If no TTS (text-only response)
- RESPONDING -> IDLE: Audio playback complete or user stops
- ANY -> ERROR: On failure (auto-returns to IDLE)

================================================================================
JAVASCRIPT FEATURES
================================================================================

Voice Initialization:
- Checks /voice/status on page load
- Enables/disables mic button based on STT availability
- Sets up all event listeners

Audio Recording:
- Uses MediaRecorder API
- Supports audio/webm (Chrome/Firefox) and audio/mp4 (Safari)
- Echo cancellation and noise suppression enabled
- Auto-stop after 30 seconds
- Collects data in 100ms chunks

API Integration:
- Sends audio to /voice/chat endpoint
- Handles session ID for conversation continuity
- Supports skip_tts option when TTS unavailable
- Proper error handling with user-friendly messages

TTS Playback:
- Fetches audio from /voice/audio/{id}
- Creates blob URL for playback
- Automatic cleanup on completion

================================================================================
USAGE FLOW
================================================================================

1. User opens kiosk interface
2. Voice status is checked automatically
3. If STT available:
   a. User clicks mic button
   b. Browser requests microphone permission (first time)
   c. Recording starts, button shows green pulse
   d. User speaks question
   e. User clicks button again to stop (or auto-stop at 30s)
   f. Audio sent to /voice/chat
   g. User message shown in chat
   h. Assistant response shown in chat
   i. If TTS available, audio response plays
   j. Returns to IDLE state

4. If STT unavailable:
   - Mic button is disabled
   - User can still type questions
   - Text chat works normally
